页面框架与安全区统一方案

给「连接页标题贴着状态栏、底部版本贴着手势条」这件事出的稿子。先看方案，认可了再改代码和现有页面稿。

先纠正我上一版的两个错。上一版我写了「边距统一 20dp」「标题统一 28sp」，这两条都不成立： 20 不在 design-language.md 的间距刻度里（刻度的 4、8、12、16、22、32）， 而 34 / 28 / 22 三档标题在规格里本来就有各自的用途，不该合并。 这一版改成只用已有的刻度，并且把标题按原规格套回去。

一、现在为什么会贴

应用用了 enableEdgeToEdge()，内容从屏幕最上面开始画，本来就压在系统状态栏下面。三个页面各写了一套边距，结果只有两个页面做了避让：

项目连接页（Journey）照片页规格里应该是
状态栏避让没有有全部要有
手势条避让没有有全部要有
左右边距22dp16dp二选一，全套统一
主标题34sp28spLarge 34 / Title 28，本来就该不同
状态页标题20sp—22sp（Title 2），20 不在规格里

所以真正要修的只有三件：连接页补两个安全区、连接页那几个 20sp 的状态标题改成 22sp、左右边距三个页面选同一个值。标题的 34 / 28 之分是对的，不动。

二、和主流应用对不对得上

按你说的「跟哔哩哔哩这些别太奇怪」逐项对一遍：

项目主流做法本方案对不对得上
系统栏避让 所有应用都避让状态栏和手势条 statusBarsPadding() + navigationBarsPadding() 一致。这就是这次真正要修的
左右边距 Material 规范和哔哩哔哩、微信这类列表页都用 16dp 16dp 一致（连接页从 22dp 收到 16dp）
顶部留白 有应用栏时由 44–56dp 的栏撑开；没有应用栏的大标题页，标题离栏底约 16dp 安全区 + 16dp 一致
标题层级 页面大标题 28–34sp，区块/状态标题 20–22sp 34 / 28 / 22 三档（沿用现有规格） 一致
标题样式 哔哩哔哩、微信、飞书顶部是一条 44–56dp 的应用栏：左边返回、中间 17–20sp 标题、右边操作 没有应用栏，页面里直接放 34sp 大标题（iOS 大标题那种路子） 不一致，见下面的说明
这一条要说清楚：如果目标是「看起来和哔哩哔哩一样」，那么真正差的不是间距，而是顶部有没有一条应用栏。 哔哩哔哩那种是「系统状态栏 → 44–56dp 应用栏（返回 / 标题 / 操作）→ 内容」，标题一直贴在栏里，不占内容空间。 现在这套是 iOS 大标题的路子：没有栏，标题直接进内容区。

两种都是主流，但混着看就会觉得「怪」。这次我建议只修安全区和边距，保持大标题路线 —— 换成应用栏是一次真正的改版（返回放在哪、标题居中还是左对齐、滚动时标题怎么收起都要定），不该塞进一个间距修复里。

你要走应用栏那条也能做，那就单独开一份稿子，别和这次混在一起。

所有页面套同一层框架，页面里只写内容，不再各自处理系统栏。数值全部取自现有刻度，没有新数字：

五、验收

  • 三个页面标题到状态栏的距离一致，都是安全区之下 16dp。
  • 底部版本行离手势条 16dp；「导出日志」仍在这一行右侧。
  • 三个页面左右边距都是 16dp，切换页面时文字不会横向跳。
  • 「找不到相机」「Wi-Fi 密码错误」这类状态标题用 22sp，和规格一致；连接页主标题仍是 34sp、照片页仍是 28sp。
  • 密码页弹出键盘时输入框不被挡住。
  • 小屏（720×1280 级别）上标题和底部行都还在屏幕内。

34sp（现在） 连接页只有一个决定，大字把它点明；和 iOS 一整套观感一致 和下面 13sp 的说明文字落差大，有人会觉得「拔出来」；长标题（自动连接已取消）折行时更占高度
28sp（降一档） 和照片页、下载页统一，切页面时标题不跳；标题和正文的比例更收敛 连接页少了一个视觉焦点，和 iOS 那种大标题路子就分开了；规格里 Large Title 那一档会没人用
我的看法：「看着突兀」主要是标题紧贴状态栏造成的，不是 34sp 这个值本身。上面两张图都已经补了 16dp 间距， 34sp 那张现在看着也就不撞了。所以倾向先不动字号，等安全区修完在真手机上看一眼再定；真要降，改成 28sp 是改一个常量的事，随时能退。
关于模拟机里的状态栏：那一条是「系统状态栏」的占位，应用自己不画它。稿子里把时间和信号放在状态栏的垂直中线上、并在顶部留出物理边距，是为了照真机的观感；中间的圆点是小米 15 那种居中打孔前摄，只用来解释顶部那块留白，不是应用要画的东西。
