# Z-Sync 产品需求

本文是背景、约束和功能范围。技术实现、进程里谁和谁传数据，在 [技术架构](architecture/architecture.md)。可验收的故事在 [需求与任务](backlog/backlog.md)，做到哪一条在 [任务清单](backlog/task-tracker.md)。人怎么走在 [使用路径](architecture/user-journey.md)。

## 背景

产品名是 **Z-Sync**，取「快速连上」。安装名、包名和界面都不写相机品牌。它不是相机厂商的官方软件。

相机是尼康 Z30。手机在小米 15（HyperOS）和一加 9RT（ColorOS）上测过。

要解决的是：官方应用把整部手机切进没有互联网的相机热点，连接要来回跳设置；免费传图应用还有下载数量限制。Z-Sync 只传原片，下载张数不设上限。

## 要服从的四条

1. 少在相机上操作。第一次配好之后，日常只在手机上点连接。
2. 两边都记住对方。手机记住热点名称、密码和自己的 PTP 身份。相机记住自己的热点密码。
3. 重启之后还能连。不重新输入密码。热点已经开着时，目标是 1–2 秒。
4. 连上之后手机继续上网。相机 socket 只走相机 Wi-Fi，蜂窝和手机默认网络仍可上网。
5. 传照片时优先保住相机网络。PTP 断流先恢复 PTP，不主动释放仍有效的热点。

官方有两种接法。Z30 稳定能用的是相机当热点（AP）。手机或路由器当热点（STA）在 SnapBridge 兼容表里对 Z30 是不支持。菜单里的「连接到计算机 → 搜索 Wi-Fi 网络」是相机去连已有的 Wi-Fi，官方用途是传给电脑。STA 如果真机菜单里有，再改日常路径。现在不押这条。

重启后仍可能要在相机上做的唯一步，是把热点重新打开。没有可靠的办法用蓝牙把关着的热点叫醒。蓝牙以后可以用来认设备、写时间和位置，不用来传原片。

## 这台相机的约束

Z30 对手机只有两条无线通路（[SnapBridge 兼容相机](https://nikonimglib.com/snbr/onlinehelp/en/compatible_cameras_44.html)）：

- 蓝牙：低功耗连接、对时、写位置。
- Wi-Fi AP：相机自己当热点。没有 Wi-Fi STA。

传原片时，手机必须加入相机热点。不能做成两台设备都连家里的同一个 Wi-Fi。同一时间相机只接受一个 PTP 客户端，连之前要退出 SnapBridge。以前用 SnapBridge 连过的网络，在手机 WLAN 里忘记。

Z30 的无线规格有 2.4 GHz 和 5 GHz 两种可能。热点实际开在哪个频段，以手机连上后看到的为准，不套用「只有 2.4 GHz」这种说法。

机身没有 GPS。文件里没有 GPS，系统相册就不会出现地点。应用自己记的位置，相册看不到。

## 参照

做法对照现成实现，不从零猜包格式。

| 项目 | 拿来对照什么 |
| --- | --- |
| [AeroShutter](https://github.com/subhashraveendran/aero-shutter) | 尼康 PTP/IP：固定 GUID、双 TCP、分块下载、断线重连、`ObjectAdded`、蜂窝留在默认网络 |
| [Viewfinder](https://github.com/AbandonS-ED/Viewfinder) | 缩略图网格、按选择下载、掉线停队列。端点 `192.168.1.1:15740` |
| [gphoto PTP/IP](https://gphoto.github.io/doc/ptpip/) | TCP 15740，命令连接和事件连接 |
| [furble](https://github.com/gkoh/furble)、[nsg](https://github.com/hurui200320/nsg) | 智能设备蓝牙的对时和写位置。Z30 的 UUID 还没在这台机器上对过 |

Z传把「手机当热点」和「相机当热点」分成两个入口，并把人送进系统 Wi-Fi 设置。Z-Sync 不把人送去系统设置。滤镜、LUT、边框、水印是传到手机之后再处理，和写进机身的优化校准不是同一件事。

## 当前范围

当前源码版本是 0.1.38，手机上装的也是。下面这些都在 0.1.38 上跑通过。

现在能用的：

- 只保存上一台成功连接相机的完整 SSID、密码和现有安装 GUID。第二次连接只重连这台；新相机成功连接后覆盖上一份资料。不维护多台凭据列表或完整连接历史。
- 密码只输入一次。不从系统「设置 → WLAN」去连相机。系统会问一次是否允许加入。
- 热点没开就继续等扫描。已经连上又断了，当前实现会重新扫描，最多再试三次。PTP 和 Wi-Fi 断线还没有分层恢复。
- 连上后，手机原来的上网可以还在。界面能看出外网是否断了。
- 照片可以大图或列表，一屏张数可选，顺序可以最早或最新。目标目录始终按相机本地拍摄日分段，日期标题左对齐，同一天缩略图连续排列；没有日期的放在「日期未记录」。
- 点「最早」或「最新」后，回到这一序的第一张，且这张在屏幕最上面。代码已合入，见 [缺陷](bugs/bugs.md)。
- 点开才下这一张原图。先点「选择」，勾了至少一张才出现「同步到相册」。
- 同步时只显示正在下的那一张，例如 `1/4`，旁边是已保存和还剩。相册里已经有的跳过。
- JPEG 和 NEF 都进系统相册 `Pictures/Z-Sync`。
- 右上角「下载」看这次存了哪些。从那里删除，只删手机相册里的那张，不动相机。
- 照片预览里的删除，从相机存储卡删除，同一次快门的 JPEG 和 NEF 一起删，受保护的留下。
- 两个删除入口独立：下载历史删手机相册，主照片页删相机。
- 连上相机后应用挂一条常驻通知（「Z-Sync 正在运行」），保图期间不会被当成空闲应用。传图时通知换成「正在保存 1/3 张照片」这样的进度。
- 应用把日志同时写进文件，连接页底部「导出日志」可以直接分享出来。文件超过 6 小时自动清掉，同时最多留 5 个、单个 2 MB。日志看哪里、怎么发在 [给别人的上手说明](guides/setup.md) 和 [后台断流方案](solution/coloros-background-drop.md)。

下载进度的界面决定在 [下载进度](features/download-progress.md)。

## 连接与传输可靠性

这是后续连接重构的验收边界，方案见 [连接可靠性](architecture/connection-reliability.md)。

- 搜索、加入 Wi-Fi、打开 PTP 会话、加载照片和传输文件是不同状态。界面和日志不能把它们都写成「连接中」。
- 连接成功必须是 Wi-Fi 网络可用且 PTP `OpenSession` 成功。只拿到 Android `Network` 不进入照片页。
- 一轮连接尝试最多 60 秒。超时进入可恢复页面，不把超时当成密码错误。
- 人打开取消确认框时连接继续；确认取消后，加入、计时和 PTP 都停止，NetworkLease 只释放一次，不得自动再连。
- PTP 操作失败时保留 NetworkLease，先重试操作，再在同一 `Network` 上重建 PTP 会话。
- 只有 Android 明确调用当前网络的 `onLost`，或人确认取消、应用结束整个会话，才释放或重获相机网络。
- 下载队列在恢复时暂停。已完整保存的照片不重下；当前照片以后用 `GetPartialObject` 从安全偏移继续。
- 部分文件不能出现在系统相册里。完整写入后才提交到 `Pictures/Z-Sync`。
- Wi-Fi 密码只在系统明确报告认证失败时失效。热点没开、系统超时和 PTP 失败都不清密码。
- 传输期间应用退到后台，用前台服务持有连接，并在通知里显示保存进度。**实测结论：小米 / HyperOS 把省电策略设成「无限制」后，切后台十几分钟连接不断；一加 / ColorOS 会冻结后台应用并销毁它的 socket，应用层无解，那台机器上只在前台传。** 人划掉应用和相机待机关闭热点，仍然不承诺继续传输。细节在 [后台断流方案](solution/coloros-background-drop.md)。

## 还要做

0.1.38 之前的范围都已经落地并验过。**现在真正剩下的按优先级只有三件**，其余是更远的大功能。

### 近期（接下来做的）

1. **分批加载。** 相机里照片多时不要一次把全部预览读完，默认只加载最近 100 张；再给一个按时间（最近一周 / 半年）或按张数选范围的选项。没有范围选项时，列表顶部要说明当前加载的是什么。
2. **加载进度。** 照片页状态行和通知都显示 `231/1000` 这样的进度，而不是只写「已显示 231 张」或「正在运行」。做法是先把 handle 枚举完拿到总数，再逐张读 info 和缩略图 —— 这也是第 1 条的前置。方案在 [加载进度](solution/loading-progress.md)。
3. **页面细节优化。** 具体项待列，先把已经知道的两条放这里：
   - 照片页副标题 13sp，和 28sp 的大标题并排偏小，看着断层。
   - 连接页和照片页右上角的元素不一样（照片页是「已连接 · 外网中断」+「下载」，连接页是空的），要确认是想要的还是该统一。

### 后续大功能

- 地点。优先在快门前把位置交给相机。相机不写时，同步 JPEG 只补 GPS，不改画面，不改拍摄时间。NEF 不改字节。定位权限只在打开「记录拍摄地点」时要。
- 拍照风格：把一套优化校准写进机身，只影响 JPEG。拨盘在 AUTO 时不写，提示拨到 P 或 U1。数字在 [拍照风格](features/picture-styles.md)。
- 边框：从相册选一张 JPEG，在下面接一条底栏后另存。原图不缩放、不覆盖。底栏高度是原图高度的 12%。左是机型和「SHOT ON」，中是圆点和分割线，右是焦距、光圈、快门、ISO 和日期，有 GPS 再加经纬度。不做题字、色块和印章。NEF 不做。一次一张。

### 有条件才做

- 重连 + 续传：掉线后指数退避重连，大文件从 `.part` 断点继续。社区主流做法（`AchooLuv/NikonLink`、`aero-shutter-mobile`），代码里已有 `pausedSync` 半成品，tag 是 `deferred/reconnect-resume`。**前提是相机热点还在** —— 相机断开会自己关 Wi-Fi，Z30 没有「保持开启」设置，所以续传前要人重新打开热点。只有真遇到同一台机器上频繁断才值得做。

### 不做

- 用蓝牙把关掉的热点叫醒。公开资料不够。
- 帮助（QL-22）、反馈（QL-23）。
- 连接后自动同步今天未保存的 JPEG。传输只由人选择媒体后手动开始。

界面当前用暗色，稿在 [界面稿](design/index.html)。

## 风险

- 速度上限由这台机身实际开出的频段决定。界面上的速度用实测，不写估计值。
- 蓝牙唤醒热点并读出当次密码，没有完整的公开格式。
- 写位置用的蓝牙 UUID 来自别的 Z 机身。这台对不上时，改为同步 JPEG 时补 GPS。
- 国行固件可能拒绝快门前写入位置。

## 延期

- 多相机凭据列表和完整连接历史（QL-06）延期到真实需要第二台相机时再评估，原验收保留在 [多相机](features/multi-camera.md)。
- 用户可配置的多品牌热点前缀（QL-07）同期延期。当前 Z30 扫描仍使用集中定义的 Nikon 规则，但不做用户可编辑前缀。
