# 尼康 Z30 统一会话与延迟批量删除方案 (Unified App-Mode Deletion Protocol)

## 1. 核心会话与删除策略
*   **单一应用模式**：连接相机后，仅发送一次 `0x9435`（参数传 `1`）以开启应用模式[cite: 5]。在整个会话期间，**绝对不要**将其切回 `0`[cite: 5]。
*   **纯净删除指令**：执行删除时，只发送标准的 `DeleteObject(0x100B)` 指令[cite: 5]。
*   **零附加操作**：在删除指令的前后，不要夹带任何模式切换指令，不要夹带开启取景的指令，也不要添加固定的延时[cite: 5]。

## 2. 兜底方案：延迟批量删除 (Deferred Batch Deletion)
如果上述纯净删除策略在 Z30 上被拒绝，或者删除后相机屏幕依然发生强制跳转，则采用此兜底机制：
*   **前端静默隐藏**：用户在 APP 端点击删除时，仅在前端 UI 层面将照片隐藏，不立即向相机下发删除指令[cite: 5]。
*   **合并时机执行**：将所有待删除的照片任务缓存，等到用户准备进入“遥控拍摄页”或“开启取景”之前，一次性批量发送删除指令[cite: 5]。
*   **视觉无缝化**：通过这种方式，将删除操作引发的系统 UI 跳转，与开启取景时本就要发生的画面切换合并为一次，从而在视觉上消除违和的跳转感[cite: 5]。
