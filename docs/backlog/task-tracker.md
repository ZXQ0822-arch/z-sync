## BUG-01 传图过程中热点断掉

**状态：** ✅ 已完成。代码在 0.1.21 里。

**依赖：** 无。先于 QR。

**说明**

传图时 PTP 失败不能被当成 Wi-Fi 已丢失。现场记录见 [传图过程中热点断掉](../bugs/bugs.md)。

**验收**

- [x] PTP 超时或 TCP 关闭时，先记录 PTP 错误，NetworkLease 仍在。
- [x] 在同一个 `Network` 上重试操作或重建 PTP 会话，照片队列暂停但不丢失。
- [x] 只有 Android 明确 `onLost` 才重获 Wi-Fi。
- [x] 恢复后从当前文件的安全偏移继续；已经完整保存的照片不重下。
- [x] 整段日志里不能出现「PTP 错误 → 应用主动 release → 手机离开热点」。

## QR-01 统一连接状态模型

**状态：** 未完成

**依赖：** 无。后面的 QR 都依赖这一条。

**说明**

建立 `ConnectionCoordinator`，把人的流程、界面、Wi-Fi 网络和 PTP 会话分成正交状态。扫描不能自行加入；连接成功必须等到 PTP `OpenSession`。用注入时钟实现 60 秒连接计时，用 generation token 作废旧回调。

**验收**

- [ ] 第一次、第二次自动连接和第二次手动连接都能映射到 [使用路径](../architecture/user-journey.md) 的页面。
- [ ] 首页和找不到相机页只扫描，不产生 JOIN。
- [ ] 连接成功要求 NetworkLease 和 PTP 会话都可用。
- [ ] 取消确认打开时连接继续；确认后只清理一次，不能再次 JOIN。
- [ ] 60 秒超时由注入时钟测试，不依赖真实等待。
- [ ] 旧 generation 的扫描、网络和 PTP 回调不能改变新连接。

**自动测试**

在 `shared` 写状态转移测试，覆盖每个页面的正常出口、取消、认证失败、连接超时、PTP 恢复和乱序回调。提交前运行 `./gradlew :shared:test`。

<a id="qr-02"></a>

## QR-02 持有相机网络租约

**状态：** 代码已合入，已装入 0.1.21。`feature/qr02-hold-lease` 已快进到 `master`。PTP 失败不释放租约，同一 SSID/BSSID 复用现有请求。手机验收还没做。

**依赖：** QR-01。

**说明**

把 `WifiNetworkSpecifier`、`requestNetwork`、回调和当前 `Network` 收进 `NetworkLease`。同一个目标已有有效租约时复用，不先 `release()`。只有人确认取消、应用结束相机会话或 Android 明确 `onLost` 才结束租约。

**验收**

- [x] PTP 错误不会调用 `unregisterNetworkCallback`。
- [x] 同一 SSID/BSSID 的重复连接请求返回现有租约。
- [x] `onAvailable`、`onLost`、取消和新 generation 乱序时只保留一个有效租约。
- [x] 相机 socket 由 `Network.socketFactory` 创建，默认上网网络不被全进程绑定到相机热点。
- [x] 密码只在明确认证失败时失效。

**自动测试**

用假的 ConnectivityManager 记录 request、unregister 和回调顺序；断言每个租约只释放一次，PTP 事件没有释放权限。

## QR-03 在同一网络恢复 PTP

**状态：** 代码已合入，已装入 0.1.21。`feature/qr03-ptp-session` 已快进到 `master`。断线、超时和 `SessionNotOpen` 走同一套 1、2、4 秒恢复。手机验收还没做。

**依赖：** QR-01、QR-02。

**说明**

新增 `PtpSessionManager`。把预期断线统一成可恢复错误；先重试读操作，再在同一个 `Network` 上关闭并重建命令 TCP、事件 TCP 和 `OpenSession`。只有 NetworkLease 报 `onLost` 才升级到重获 Wi-Fi。

**验收**

- [x] `camera closed the connection`、socket 超时和 `SessionNotOpen` 走同一套有界恢复。
- [x] 恢复等待 1、2、4 秒，同一时刻只有一轮。
- [x] 会话恢复期间照片页和已经加载的缩略图保留。
- [x] `CameraRoll.close()` 与进行中的 PTP 操作串行，不从另一个线程直接关 socket。
- [x] 事件连接持续读取；空闲保活不与传输事务并发。

**自动测试**

假的 PTP wire 按步骤注入 EOF、超时、`SessionNotOpen` 和恢复成功；验证没有 Wi-Fi release，事务按新会话重建。
