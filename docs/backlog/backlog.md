# Z-Sync 需求与任务

实现用 Kotlin 和 Compose，先做 Android。真机一次只验收一个任务；不连设备就能写完的代码可以同时做。

相机是尼康 Z30。菜单按中文界面写。无线频段和蓝牙定位是否还能写入，以 Spike 实测为准。

产品名 Z-Sync。它是连接和传图工具，不是相机厂商的官方软件。

> **这一份是历史。**写于 0.1.16 之前，里面的可行性结论、Spike 计划和故事大多是当时的推演。已经被推翻或已经实现的，都不在这里更新。
>
> 想知道现在能做什么看 [需求](../requirements.md)，想知道每条做到没有看 [任务清单](task-tracker.md)。

## 可行性（桌面结论，还没上真机）

这些是查手册、libgphoto2 和现有开源项目之后能确定的事。真机还没跑，所以下面凡是写着「待 Spike」的，都不算已经能做。

| 需求 | 结论 |
| --- | --- |
| 少碰相机、两边记住、重启快连 | 第一次要输入密码并点一次系统允许。之后密码、GUID 和蓝牙配对都留在各自设备里。热点已开时目标 1–2 秒。Z30 只能做相机热点。用蓝牙把关着的热点叫醒，公开资料不够，不放进第一版承诺。 |
| 连着相机时手机继续上网 | 设计上 PTP 只占用相机网卡，默认网络仍是蜂窝或原来的 Wi-Fi。小米 15 是否真能同时上网，待 Spike。 |
| 传原文件、按拍摄日浏览 | 做得到。PTP/IP，端口 15740，分块用 `GetPartialObject`。用户媒体目录始终按相机本地日期分组，不设日期筛选。 |
| 相册里的时间和手机拍摄一致 | 写入 `MediaStore`，小米相册按 `DateTimeOriginal` 对应的 `DATE_TAKEN` 排序，和手机拍的穿在一起。不按同步时间排到今天。不压缩，不改像素，不改拍摄时间。 |
| 地点 | 相机没有 GPS，机身和原片都不显示地点。小米相册只认照片里的 GPS。蓝牙在快门前写入是否被国行固件拒绝，待 Spike。写不进去时，同步 JPEG 只补 GPS，相册才能出现地点。 |
| 点一个滤镜，相机按这套参数拍 | 方向对，拨盘要先放在 P 或 U1/U2/U3。手机拧不了拨盘。写入走尼康私有操作 `SetPictCtrlData`（0x90CD），Z30 这份数据的格式待 Spike。抓不到这个操作，功能就只保留配方管理，不显示「已应用到相机」。 |
| 变成富士机内胶片模拟 | 做不到。Z30 没有那些模拟。能预制的是别人已经为 Z30 写好的优化校准配方，看起来接近胶片，并不是富士原厂模拟。Classic Chrome 没有对等配方。 |
| iOS | 现在不做。协议放在公共 Kotlin 模块里，避免以后重写。 |
| 边框水印 | 以后再做。做法已经记下：从相册选一张 JPEG，在下面接一条底栏，另存，原片不改。当前版本不进界面，也不排进 T1–T6。 |

## 需求

每条都是可以单独验收的故事。后写的故事依赖前面的连接。

### A. 连接

**A1.** 我打开 Z-Sync，相机热点已经开着，点一次「连接」，不用再输入已经保存过的密码，就进入照片列表。

**A2.** 第一次连接时，我只输入一次相机屏幕上的密码。之后密码还在。

**A3.** 热点没开时，我看到的是打开热点的三行菜单说明。热点一出现，连接自己继续，不用我再点第二次。

**A4.** 连不上时，用一句话说明原因：热点没开、密码错了、或者官方 App 还占着连接。

**A5.** 手机和相机都重启之后，我不重新输入密码，也不在相机菜单里重新配对。热点开着时，点一次连接就进入照片列表。

**A6.** 传图进行时，手机原来的网络还在。我能打开网页或收到消息。若外网实际断了，界面直接写明，不显示成已经连着网。

### B. 传照片

**B1.** 连上之后，我可以选择大图或竖向列表。大图一屏可以选 4、6 或 9 张，列表一行一张。两种都能看到文件大小，点开后预览，左右滑上一张、下一张。先只有缩略图，原片还没下载。看法和一屏张数会记住。

**B2.** 我看到按相机本地拍摄日分段的用户媒体时间线，同一天照片和视频自动归组，未知日期归入「日期未记录」。我可以用 `全部`、`JPEG`、`RAW / NEF`、`MOV`、`MP4` 筛选，再按 handle 勾选多项。切换格式不丢选择、不重读目录。

**B3.** 同步进手机自带相册。排序和手机自己拍的一样，按拍摄时间，不按同步时间。不压缩，不改画面，不改拍摄时间。

**B4.** 同步可以中断后续传，已经传过的不会再传一遍。

**B5（已取消）.** 不做连接后自动拉取「今天还没传的 JPEG」。传输只由我选择照片后手动开始；手动队列仍支持暂停、恢复、断点续传，以及传输期间前台执行。

**B6.** 我在预览里删掉一张。相机里的文件一起删掉。已经进手机相册的那份也删掉。同一次快门的 JPG 和 NEF 一起删。删之前要我确认。

**B7.** 我可以勾选多张再删除。规则和删一张相同。相机上设了保护的那张会留下，并说明原因。

### C. 地点

**C1.** 我打开位置之后，小米相册里这张 JPEG 能显示在哪拍的，和手机拍摄的照片一样。优先在快门前写进相机。

**C2.** 相机没写上地点时，同步 JPEG 只补 GPS。不改画面，不改拍摄时间。没有这一步，相册不会出现地点。

**C3.** 我拒绝定位权限时，传照片仍然可用，只是没有地点。

### D. 照片风格

**D1.** 我不会用手动挡。我把拨盘拨到 P，或拨到已经准备好的 U1。在手机上点一个预制风格，相机接下来拍的 JPEG 使用这套优化校准、白平衡和动态 D-Lighting。

**D2.** 预制风格是一份可以增删的清单，而不是写死在代码里。第一批采用已公开、并声明适用于 Z30 的配方，详情里写明作者和出处。名字用配方自己的名字，例如 Fujichrome、Classic Slide，不写成富士原厂模拟。数字在 [拍照风格](../features/picture-styles.md)。

**D3.** 拨盘停在 AUTO 时，手机告诉我拨到 P 或 U，并且不写入。

**D4.** 我可以看每一条风格的参数，也可以以后自己加一条。自己加的和预制的用同一套字段。

**D5.** 下发失败时，手机说明没写进去，相机保持原设置。

风格字段固定为：

- 优化校准种类（标准、中性、鲜艳、单色，或创意项如 Dream、Somber）
- 效果强弱
- 快速锐化、锐化、中间调锐化、清晰度、对比、饱和度
- 白平衡和偏移
- 动态 D-Lighting
- 高感光度降噪
- 可选的 ISO 上限，只作提示，不强制改相机 ISO，除非 Spike 证明写入安全

U 档的用法：手机不替用户注册 U1。用户如果希望关机还在，就在相机菜单里把当前设置存进 U1。Z-Sync 负责把「当前这一套」写对。说明书写明 U 档不会保存「管理优化校准」菜单，所以第一版不依赖 C-1 到 C-9 槽位。

### E. 边框（以后再做）

当前版本不做。下面记着，免得以后重想。拍完、原片已经在手机相册里之后才用。和「风格」不是一件事：风格写进相机，边框只在手机上另存一张。

**E1.** 我不连相机，从手机相册选一张 JPEG。照片下面接一条底栏，拍摄信息自动填上。

**E2.** 底栏可以白底或黑底。左边是 SHOT ON 和机型，中间一个圆点，右边是焦距、光圈、快门、ISO，下一行是日期和经纬度。机型、参数、日期和位置可以各自关掉。没有这些信息时看到兜底文案，并可以改字。

**E3.** 我点另存。新图进 `Pictures/Z-Sync`，拍摄时间照抄原片，所以在相册里排在旁边。原来那张的像素、时间和文件都不动。预览不占用原图像素，点保存才画大图。

一次一张。中间不用品牌商标图。这一版不做 NEF，不做多张一起套。

### F. 现在不做

- iOS
- 用手机切换 P/S/A/M 拨盘
- 把官方胶片模拟的名字做成开关
- 遥控快门、实时取景
- 改 RAW 文件里的像素

## 任务

状态只有四种：待 Spike、准备做、进行中、完成。现在除了 S0，其余都是待 Spike。S0 的结论如果否决了某条需求，就改需求，不硬做。

### S0 真机 Spike

在 Mac 上装 Android Studio，一加 9RT 按 [开发流程](../process/dev-loop.md) 用数据线接上。先不写正式界面，用一个临时调试页或桌面脚本把事实记到 `docs/spike/`。

| 编号 | 做什么 | 完成时留下什么 |
| --- | --- | --- |
| S0.1 | 确认 Mac 能编译一个空的 Android 工程，小米 15 能装上并被 `adb` 看到 | `docs/spike/00-environment.md` 写 Android Studio 版本、手机系统版本、装得上 |
| S0.2 | 先看国行菜单里有没有 STA：相机连接手机热点，或基础设施模式。有就记菜单路径。再按 AP 打开相机热点，手机加入，连上 TCP 15740，记下操作码、属性码、固件版本、热点频段和信道 | `docs/spike/01-device-info.md`。要看到型号是 Z 30，并写明 STA 菜单在或不在 |
| S0.3 | 热点已开的情况下，从点连接到会话打开，记三次耗时。会话开着时，用手机默认网络访问一次外网 | 三次数字，以及外网是否通。有两次落在 2 秒内，A1 的目标就保持。外网不通就改 A6 |
| S0.4 | 下一张 JPEG 和一张 NEF。记 MB/s。写入系统相册。对比相机原文件和相册里的文件，字节应一致，拍摄时间不应变成同步时间 | 速度数字、字节是否一致、相册时间是否正确 |
| S0.5 | 在机身上手动改一次优化校准，读 `0x90CC`。再试写 `0x90CD`，拍一张 JPEG，看风格变了没有。拨盘分别停在 P 和 U1 各试一次 | 能写或不能写。不能写就收窄 D1 |
| S0.6 | 看蓝牙广播里有没有智能设备服务 `0000de00-3dd4-4255-8d62-6dc7b9bd5561`。有的话试写一次时间。国行固件若拒绝位置写入，记下来 | 有或没有，以及位置写入是否被拒绝。服务不在，或写入被拒绝，就把 C1 的「写进相机」降级成只在手机上补 JPEG |
| S0.7 | 手机关机再开、相机关机再开。不重新输入密码。记录还要不要进相机菜单，以及机身是否再次要求允许 | 重启后的步骤清单。多出来的相机操作写进 A5 的限制 |
| S0.8 | 把 S0.2 到 S0.7 收成一页：哪些需求保持，哪些改范围 | `docs/spike/conclusion.md` |
| S0.9 | 对一张未保护的 JPEG 发 `DeleteObject`（0x100B），确认卡上没有了。再试一张带保护标记的，应拒绝。若是 JPG+NEF，记下要不要按两个句柄各删一次 | 能删或不能删。不能删就收窄 B6、B7，只删手机相册里的副本 |

S0 做完之前，不把功能当成已经可用。代码按下面的实现切片先写，用单测验收。真机结论如果否决了某条，就改对应切片，不硬做。

### S0 之后，按这个顺序

每一项都等前一项在小米 15 上用过，才算那项验收完成。这是真机顺序。代码可以先按实现切片写。

1. **T1 连接。** 实现 A1–A6。记住密码和 GUID，PTP 只走相机网卡，默认网络继续上网。重启后不重新配对。
2. **T2 浏览。** 实现 B1、B6、B7。大图和列表、预览滑动、单张和批量删除。删除以 S0.9 为准。
3. **T3 同步。** 实现 B2–B4。选择、原样下载、相册时间、断点、去重。
4. **T4 地点。** 实现 C1–C3。范围以 S0.6 的结论为准。
5. **T6 风格。** 实现 D1–D5。范围以 S0.5 的结论为准。先做预制清单和参数页；只有 Spike 证明写得进相机，才做下发按钮。

T6 内部再拆开，到时候一次只做一行：

- T6.1 配方数据文件和列表
- T6.2 参数详情页
- T6.3 读取相机当前优化校准，和某一条配方对照
- T6.4 在 P 档下发并拍照验证
- T6.5 U1 下发的行为，按 S0.5 的记录决定是支持还是提示用户
