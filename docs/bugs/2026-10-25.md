# 2026-10-25 这一轮的问题

2026-10-25 在小米手机上测 0.1.28 时记下来的问题。单独放一份，不混进 [bugs.md](bugs.md)：那边大部分是已经改完、等真机确认的旧条目，这一轮还在查。

## 传图时切到别的应用，连接断掉、相机热点跟着关

- [x] 小米已解决（2026-10-25）。前台服务 + 省电策略「无限制」，实测切后台 11 分钟以上不掉，热点不关。ColorOS 无解，不再处理。见 [coloros-background-drop.md](../solution/coloros-background-drop.md)。

2026-10-25 补：一加（ColorOS）上的 0.1.29 日志把这个查清楚了，原来的三条猜测里第 1 条是对的，但有更狠的一步：

1. 应用进后台，缩略图还在刷，`cpuLoad=85`。
2. ColorOS 进 `StrictMode-1`，`freezeAllApps` 冻住进程（**前台服务没挡住**，日志里 FGS 是启动成功的）。
3. 同一毫秒 `netd: destroyAllSocketForUid:10027`，2 个 PTP socket（command + event）被销毁。
4. 相机收到 RST/FIN，结束会话，关掉自己的 Wi-Fi。手机 5.3 秒后判 beacon 丢失，OPPO 再延迟 4 秒，共 9.4 秒一直假显示「已连接」。
5. 应用被冻着，解冻后心跳才发现 socket 没了，而且失败被吞，于是静默跳回连接页。

已经改的（`bug/background-freeze`）：申请电池白名单并提示（P0）、心跳失败判会话丢失（P1）、后台停止加载加上限节奏（P2）、修事件通道 30 秒超时。

2026-10-25，小米。连着相机热点正在传照片，没有退出 Z-Sync，只是切到 B 站，用移动数据看了十几秒视频。回来时相机通信已经停了，相机热点也自己关了。

复现路径：

1. 连上相机热点，开始「同步到相册」。
2. 切到别的应用（例如 B 站），并且用移动数据。
3. 十几秒后回到 Z-Sync。

这是「断流问题怎么分」里没单列的一种：人在用应用，只是把它放到后台。可能的触发者有三条，日志里必须分开，不能合成一句「相机 Wi-Fi 不稳定」：

1. **进程被系统冻结或回收。** Z-Sync 现在没有前台服务，`requestNetwork(WifiNetworkSpecifier)` 只挂在进程上。进程一被冻结或回收，系统就释放这条请求，手机离开热点，相机察觉没有客户端连着，再自己关热点。这一类就是「关掉应用后相机热点马上灭」那条，只是这里是人切走、不是划掉，所以进程可能稍后才被收。
2. **手机把不能上网的热点丢掉。** 相机热点没有外网。B 站要流量时，系统或 MIUI 的「WLAN 助理」可能把默认网络切到移动数据，对这条路发 `CMD_UNWANTED_NETWORK`。这一类就是「空闲时手机离开相机热点」那条，只是这里由别的应用要网触发，不是空闲。
3. **相机待机定时器。** 自定义设定 c3 默认约 30 秒。应用被冻住、心跳发不出去时，相机会按待机计时关热点。这一类就是相机自己关热点那条。

日志要能回答「谁先发生」：

- 有没有 `camera network lost` / `onLost`，以及它相对进程被冻结的时间点。
- 应用进程状态：`adb shell dumpsys activity processes | grep app.zsync`，或者 `dumpsys procstats`，看是被 cached、frozen 还是已退出。
- logcat 里的 `CMD_UNWANTED_NETWORK`、`locally_generated=1`，以及 MIUI/OPlus 网络助理相关的行。
- 断开之前相机上的传输灯还在不在闪（人当时看没看相机）。

修的方向（先不实现，等日志确认是哪一类）：

- 传图中不让进程被冻结：用一个前台服务持有 NetworkLease 和一个可见通知，把「正在保存 N 张」放进通知。这条是「关掉应用后相机热点马上灭」里已经写下的后续安排。
- 前台服务同时负责保活心跳：进程还活着时每 30 秒发 `GET_DEVICE_INFO`，避免相机 c3 待机。
- 应用只在 Android 明确 `onLost` 时才重获 Wi-Fi；PTP 失败不升级成 `NetworkLost`（和「传图过程中热点断掉」一致）。

验收：

- 传图时切到别的应用（含用移动数据看视频）至少 1 分钟，回来照片继续传，不需要重连。
- 切走期间相机热点不关。
- 万一仍然断，日志能指认是上面 1/2/3 里的哪一条。

## 相机热点关掉后，手机还显示尼康连着，照片页也不报断

- [x] 应用侧已改（心跳失败判会话丢失），小米上验证通过。系统侧那个 9 秒假显示是 ROM 行为，改不了。

2026-10-25 补：一加日志量出来是 beacon 判定 5.3 秒 + 厂商延迟 4 秒 = 9.4 秒。应用侧的「不报断」已经由心跳判丢失修掉（见上一条）。

2026-10-25。相机的 Wi-Fi 已经关掉了，但小米手机上仍然显示 `NIKON_Z_30_xxxxx` 是「已连接」。Z-Sync 也还停在照片页，没有任何断开提示，看起来像照片还能看。

现象拆成两条：

1. **系统侧：**相机热点没了，手机的关联没有立刻掉，状态栏/WLAN 列表还挂着这个 SSID。
2. **应用侧：**照片页不报断。应用只在 `onLost` 时才离开照片页，而 `onLost` 要等手机的关联超时，可能几十秒到一分钟。

代码现状：

- `AndroidCameraWifi.onLost` → `LinkEvent.NetworkLost` → 离开照片页 + `wifi.release()`。这条路本身是对的，但它依赖系统的关联超时。
- 空闲心跳 `CameraRoll.keepaliveIfIdle()` 每 30 秒发一次 `GET_DEVICE_INFO`。它失败时只写一行 `ptp keepalive skipped`，**不上报会话丢失**。所以相机已经没了、TCP 已经死了，应用也不动。
- 照片页没有「连接已断开」的状态；要么等 `onLost`，要么等下一次真正的 PTP 操作失败。

要改的方向（先记录，等日志）：

- **心跳失败要当成会话丢失。** TCP 已经连不上相机时，走和 `sessionLost()` 相同的路径：照片页先显示「相机已断开」，然后回连接页。
- **检测要快。** 现在最快也要等 30 秒心跳。连着的时候可以把空闲探测缩短（例如 5 到 10 秒一次），或者用一次短的 TCP 探测。
- **检测到丢失后释放 `WifiNetworkSpecifier` 请求**，让系统把这条已经没有关联的 Wi-Fi 掉掉，状态栏不再假显示「已连接」。不靠「伪造热点一直有网」盖住问题。

验收：

- 关掉相机热点，10 秒内照片页出现「相机已断开」并回到连接页。
- 同一时间手机 WLAN 不再显示那台相机「已连接」。
- 日志能指认是 `onLost` 先到，还是心跳/TCP 探测先发现。

## 连接页标题贴着状态栏，底部版本贴着手势条

- [ ] 方案已出（`docs/design/pages/frame-spacing-proposal.html`），等确认后再改。0.1.28 上看到，小米。两张截图：「自动连接已取消」页、「正在自动连接」页。

页面最上面的标题（「自动连接已取消」「正在自动连接」）离系统状态栏（时间、信号那一行）太近，几乎贴在一起；底部的版本号 `v0.1.28 (28)` 也贴着下面的手势条。按微信、飞书、微博那种正常间距来，上下都留出系统栏的高度再加一点呼吸空间。

原因（代码）：

- 应用用了 `enableEdgeToEdge()`，内容会画到状态栏和手势条下面。
- `ConnectScreen` 和 `PhotoScreen` 都加了 `statusBarsPadding()` / `navigationBarsPadding()`，但 `JourneyScreen` 的根布局 `JourneyChromeScreen` 只有 `Box(fillMaxSize).background(Phone)` + `Column(padding(horizontal = 22.dp, vertical = 28.dp))`，**没有吃系统栏 inset**。那 28dp 是从屏幕最顶上算的，所以标题正好压到状态栏下面。
- 底部版本号只有 `padding(top = 18.dp)`，没有 `navigationBarsPadding()`。

要改的方向（先记）：

- `JourneyScreen` 根布局加 `statusBarsPadding()` 和 `navigationBarsPadding()`，和另外两个页面一致。
- 在 inset 之上再留一点间距（现在的 28dp 可以保留或微调），让标题不贴状态栏；底部同样留一点。
- 连接页其它元素（「取消连接」按钮、步骤、热点列表）都在这一个 Column 里，加 inset 后整页一起下移，要顺手对一遍整页是否还和设计稿一致。
- 顺便统一检查所有页面，别的地方在 edge-to-edge 下有没有漏 inset。

验收：

- 「自动连接已取消」「正在自动连接」等连接页，标题顶端到状态栏之间有明显间距，和微信/飞书那一档一致。
- 底部版本号不贴手势条。
- 照片页、连接页原来的间距不变。

## 后台传完图之后，相机的 Wi-Fi 会自己关掉

- [ ] 记录。小米 15 上看到过，但**没有复现出来**，先不追。

2026-10-25，小米。选 7 张下载，点「下载」后切到别的应用，让它在后台传。传完之后回来，发现连接断了，相机的 Wi-Fi 也关了。

随后按三种顺序试：
1. 后台传 → 传完 → 断开（第一次）
2. 前台看着传完 → 没断
3. 后台传 → 传完 → 没断

所以是间歇的，没有稳定复现路径。

可能的方向（都还没验证）：传完之后应用彻底空闲，被系统当成可冻结的应用；或者传完之后那一次心跳打到了相机正在收尾的会话上，被判成会话丢失。0.1.35 起加了四条「谁把会话拆了」的日志和「导出日志」入口，下次再遇到可以直接看日志定性。

结论：不改，等再次复现时带着日志再看。
