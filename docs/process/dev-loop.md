# 用 AI 开发时怎么操作手机和相机

AI 跑在 Mac 上。它能改代码、编译、安装、读日志、截手机屏幕。它碰不到相机的拨盘和菜单，也点不了第一次出现的系统确认框。怎么连上手机、`adb` 放在哪，见 [手机调试连接](dev-setup.md)。传图时优先用数据线。

产品上，连上相机之后手机还要能上网，所以应用只会把传图套接字放到相机热点上。调试时仍然用数据线：人如果在系统设置里把整部手机切进相机热点，无线调试会断，手机外网也会断。Mac 自己留在能上网的网络上。

## 一次性准备

在小米 15 上：

1. 设置 → 我的设备 → 全部参数与信息，连点版本号，打开开发者选项。
2. 打开「USB 调试」和「USB 安装」。HyperOS 里如果还有「USB 调试（安全设置）」，一并打开。这样 AI 才能安装调试包，并在需要时用 `adb` 查看界面。
3. 用数据线连上 Mac。手机上点「允许 USB 调试」，勾选一律允许。
4. 开发者选项里打开「充电时屏幕不休眠」。
5. 把 SnapBridge 划掉，并在应用信息里停用它。相机同一时间只接待一个连接方。

在相机上，国行菜单：

1. 设置菜单 → 连接至智能设备 → Wi-Fi 连接 → 建立 Wi-Fi 连接。
2. 屏幕上的名称和密码不要改。密码只在第一次告诉 AI，并且只存进手机，不写进仓库和聊天记录以外的文件。
3. 卡里放几张已经知道文件名的 JPEG，再加一张 NEF，后面对传输结果用。
4. 设置菜单里看一次固件版本，记到 `docs/spike/01-device-info.md`。

在 Mac 上确认：

```bash
adb devices
```

列表里这台小米是 `device`，才算接上。显示 `unauthorized` 时，看手机屏幕上的允许框。

## 每次让 AI 碰相机之前

按这个顺序做，然后把最后一句话发给 AI：

1. Mac 能上网。
2. 小米用数据线连着 Mac，屏幕亮着，已解锁。
3. 相机开机，电量够，热点停在「已建立连接」那一页，密码没变。
4. 拨盘放在 P。测风格时再按任务要求改到 U1。
5. 手机上的 SnapBridge 没有在跑。

发给 AI 的话用这一句：

> 相机热点已打开，手机已用 USB 连接。请安装 debug 包，抓 Z-Sync 日志，并截屏。

AI 接着做的事：安装、启动、`adb logcat`、`adb exec-out screencap`。第一次加入热点时，手机会弹出系统确认，需要人点允许。点完告诉 AI「已允许」。机身如果弹出连接确认，在相机上点允许，再告诉 AI。

## 每次出新包

每次编译要装到手机上的包，都先升版本，再装，再核对。三步缺一步，就不叫用户重试。

1. 改 `androidApp/build.gradle.kts`：`versionCode` 加 1，`versionName` 跟着改，例如 `0.1.2`（2）→ `0.1.3`（3）。
2. 编译并安装后，用 adb 核对手机上的就是这个包：

   ```bash
   adb shell dumpsys package app.zsync | grep -E "versionCode|versionName|lastUpdateTime"
   adb shell sha256sum "$(adb shell pm path app.zsync | sed 's/package://' | tr -d '\r')"
   shasum -a 256 androidApp/build/outputs/apk/debug/androidApp-debug.apk
   ```

   `versionCode` 要等于刚改的值，两个 SHA-256 要一样。对不上就重装，再核对一次。
3. 告诉用户这次应该看到的版本。连接页最下面写着 `v0.1.2 (2)` 这样的字。用户看到的和说的不一样，就是装错了包。

每次改完代码、编译完或装完，AI 都要明确告诉用户：做完了，接下来该做什么。不假定用户已经看到。

做事期间每 1 分钟报一次进度：正在做哪一条、代码有没有在改、测试过没有、提交落下来没有。人说停，或这一轮事情做完，就停。

提交只在本地，不推送，说明用英文。一个改动一次提交：权限、日志、版本号、错误显示各自分开。

连接页的日志统一用 `Z-Sync` 标签。正常步骤写 INFO，失败写 ERROR。按钮点击、发出网络请求、系统接受或拒绝、密码保存或清除，都各有一行。日志里只写密码长度，不写密码本身。

```bash
adb logcat -s Z-Sync:V
```

## 谁做什么

| 动作 | 谁来 |
| --- | --- |
| 改代码、编译、安装、读日志、截屏、看 Wi-Fi 频段 | AI，通过数据线 |
| 打开或关闭相机热点、拧拨盘、在机身上点允许 | 人 |
| 第一次的 USB 调试授权、Wi-Fi 系统确认、运行时权限 | 人点一次，之后系统会记住 |
| 看一张 JPEG 的颜色是否像预期配方 | 人看相机或相册，用一句话告诉 AI |
| 不连相机的界面和单元测试 | 只有 Mac 就够，手机可以不连热点 |

看频段用：

```bash
adb shell dumpsys wifi | head
```

日志只过滤应用自己的标签，标签定为 `Z-Sync`。日志里可以有 SSID、耗时、操作码和错误码。不要打印密码、位置轨迹和照片内容。

## 两种调试不要混在一次会话里

界面和单元测试：手机可以连着家里的 Wi-Fi 或蜂窝，方便看页面。这个阶段用无线调试也可以。

连接相机、传图、写优化校准：手机关掉无线调试，只用数据线。手机的 Wi-Fi 交给应用去加相机热点。人不要在系统设置里手工加入热点，除非 Spike 明确要求对照「手工连接」和「应用连接」。

一次会话只做 backlog 里的一个任务。做完把日志里的结论写进 `docs/spike/`，再开始下一个。
